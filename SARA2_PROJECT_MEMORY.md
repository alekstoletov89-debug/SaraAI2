# SaraAI2 — долговременная память проекта
Последнее обновление: 2026-10-15. Это рабочая заметка для продолжения проекта в новых чатах. Перед изменением архитектуры сверяться с ней и текущими файлами репозитория.

## Жёсткие ограничения
- Работать только в ветке `saraai2-oneclick-repair`, пока пользователь явно не попросит иначе.
- Не менять SaraAI1 в `%USERPROFILE%\SaraAI` и не переписывать ветку `sara/full-router`.
- Не выдавать статическую проверку или CI за реальный запуск на компьютере пользователя.
- Пользователь хочет один простой запуск двойным щелчком, без многострочных PowerShell-команд и повторения уже предоставленного контекста.
- Временная сборка должна быть без клонирования голоса жены. Голос жены не коммитить в публичный репозиторий; вернуться к нему позже, по отдельному решению.
- Не заменять полноценную архитектуру упрощённой текстовой программой молча. Если сборка текстовая/урезанная, писать это крупно и прямо.

## Компьютер и известная среда пользователя
- Windows 10, Python 3.11.9 уже использовался в `%USERPROFILE%\SaraAI\.venv`.
- Intel i5-12400, RTX 5060 8 GB, RAM 16 GB.
- Ollama на `http://127.0.0.1:11434`, основная модель `qwen3.5:9b`.
- Основной рабочий каталог SaraAI1: `%USERPROFILE%\SaraAI`; отдельная копия SaraAI2: `%USERPROFILE%\SaraAI2`.
- Принятая ранее команда запуска SaraAI2 через окружение SaraAI1 (только для диагностики старой копии, не для установщика автономной сборки):
  ```powershell
  cd "$env:USERPROFILE\SaraAI2"
  & "$env:USERPROFILE\SaraAI\.venv\Scripts\python.exe" "$env:USERPROFILE\SaraAI2\sara_agent.py"
  ```
  Обязательное правило: при ответах о SaraAI всегда давать готовую команду запуска, если она нужна для следующего шага; не заставлять пользователя собирать её из фрагментов.

## История проблем и затыков
1. В начале копии SaraAI2 отсутствовал каталог `core`; запуск `sara_agent.py` завершался `ModuleNotFoundError`. Тогда `core` временно копировали из SaraAI1. Репозиторий по состоянию этой ветки не содержит `core/`, поэтому полноценный агент с импортами `core.memory_commands` и `core.semantic_memory` в чистом ZIP не запускается.
2. Старый `start_sara.bat` искал Python только в `%USERPROFILE%\SaraAI\.venv\Scripts\python.exe`. В другой установке он сообщал `Python environment not found`; это путь к SaraAI1, а не автономное окружение SaraAI2. Не путать их.
3. Старый запуск показывал текстовый заголовок `SARA AI AGENT`, хотя пользователь ожидал голосовой режим. `sara_voice_agent.py` и полный каталог `speech/` отсутствуют в текущем репозитории. Не заявлять, что голосовой режим подключён.
4. Qwen-TTS загружался и Windows beep работал, но речи не было слышно. Это отдельная проблема аудиогенерации/воспроизведения, не доказательство исправности TTS. `flash-attn` отсутствовал; предупреждение само по себе не было подтверждённой причиной отказа.
5. Измерения прежнего TTS: загрузка модели 14.08 с, генерация 28.29 с, сохранение+воспроизведение 5.38 с. Пользователь хотел ускорить речь; 2026-10-13 была отправлена замена на Qwen3-TTS 0.6B (~2.5 GB) и ограничение токенов. Эти цифры — исторические замеры, не текущий benchmark.
6. В русскоязычной консоли возникала «кракозябра» (mojibake); были исправления кодировки и фраз Windows-маршрутизации 2026-10-13. Использовать UTF-8 и `chcp 65001`, не возвращать старые испорченные строки.
7. В проекте есть отдельные слои маршрутизации: `sara_agent.py` вызывает `tools.execute_tool`; ранее пользователь отмечал дублирующий старый роутер `core/router.py`. Не плодить новый независимый роутер без необходимости и не ломать рабочую архитектуру.
8. Пользователь хочет простые команды Windows обрабатывать быстрым маршрутизатором без загрузки E5 и без планировщика Qwen; обычный диалог — через Qwen и память. Не делать каждый вызов системной команды дорогим LLM-запросом.
9. Пользователь сообщал, что рабочий голосовой прототип был в `sara_voice_agent.py`; ранее для STT применялся GigaAM `v3_e2e_ctc`, устройство микрофона 30, частоты 48 kHz -> 16 kHz, VAD aggressiveness 2. Эти настройки исторические; не считать, что соответствующие файлы включены в текущий ZIP.
10. Ошибка при попытке заменить стартовый скрипт: он искал окружение Python в `C:\Users\user\SaraAI2` и выдавал `Python environment not found`. Для автономной сборки окружение должно создаваться рядом с файлами в `.venv`; при неудачном создании нужно удалить частичное окружение перед второй попыткой.
11. Пользователь просит не трогать СараAI1; ветка `sara/full-router` существовала до ремонта. Все новые правки этой итерации — только `saraai2-oneclick-repair`.

## Команды проверки, которые уже использовались/которые можно безопасно использовать
- Компиляция текстовой сборки: `py -3.11 -m py_compile sara2_local.py`.
- Unit-тесты: `py -3.11 -m unittest discover -s tests -v`.
- Проверка Python: `py -0p` и `py -3.11 --version`.
- Проверка Ollama: `Invoke-RestMethod http://127.0.0.1:11434/api/tags`; точная модель должна включать `qwen3.5:9b`.
- Проверка доступности API: `Invoke-RestMethod http://127.0.0.1:11434/api/chat -Method Post -ContentType 'application/json' -Body (...)` — запускать только когда нужна отдельная проверка ответа модели; не использовать это как доказательство работоспособности ярлыка.
- Предпочтение пользователя: вместо просьбы вставлять команды по одной — добавлять кнопку/один `.bat`, который соберёт диагностический лог в файл, чтобы пользователь мог прислать его обратно.

## Следующие обязательные этапы перед заявлением «готово»
1. Установщик должен безопасно создавать отдельное `.venv` для SaraAI2; при ошибке создания Python 3.11 очищать незавершённое окружение перед попыткой 3.12.
2. Добавить однонажимную диагностику, сохраняющую версию Python, файлы проекта, состояние Ollama и точное наличие модели в `SARA2_DIAGNOSTICS.txt`.
3. Отдельно восстановить недостающие `core/`/зависимости и голосовой контур из проверенного исходника, не придумывая модули и не затрагивая SaraAI1. Если исходники недоступны в GitHub, не подменять их самописными заглушками.
4. Добавить тесты установщика/маршрутизации и проверку фактического старта агента в чистом окружении Windows.
5. Только после этого выдавать ZIP как автономную полную сборку; пока называть её промежуточной текстовой сборкой.
